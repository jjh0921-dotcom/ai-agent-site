*   **수익성 근거:** 데이터는 원자재이며, 이를 가공하여 즉시 활용 가능한 인사이트로 제공할 때 가장 높은 가치를 인정받음.

# ⚙️ NicheFlow AI MVP: 프로그래밍 포스트 초안 생성 로직 설계안

## 1. 목표 정의 (Goal Definition)

**최종 목표:** 사용자가 입력한 주제(Topic)와 난이도(Difficulty)에 기반하여, 검색 엔진 최적화(SEO)에 유리하고 독자의 참여를 유도하는 고품질의 프로그래밍 포스트 초안(Draft)을 자동 생성한다.

**핵심 기능:**
1. **입력 수집:** 주제, 타깃 독자, 원하는 포스트 스타일(후크 유형) 입력.
2. **프롬프트 엔지니어링:** 입력값을 바탕으로 LLM이 원하는 구조와 톤을 갖춘 초안을 생성하도록 유도.
3. **API 연동:** 외부 데이터(선택 사항) 또는 내부 지식베이스(Knowledge Base)를 참조하여 초안의 깊이를 보강.

## 2. 프롬프트 엔지니어링 설계 (Prompt Engineering Design)

핵심은 LLM이 단순히 코드를 나열하는 것이 아니라, **'교육적 가치'**와 **'흥미 유발'**을 결합한 구조화된 콘텐츠를 생성하도록 유도하는 것입니다.

### 2.1. 시스템 프롬프트 (System Prompt)

LLM의 역할과 제약 조건을 명확히 정의합니다.

```prompt
당신은 전문적인 기술 블로거이자, 복잡한 프로그래밍 개념을 명확하고 이해하기 쉽게 설명하는 교육 콘텐츠 전문가입니다. 당신의 목표는 사용자가 제공한 주제와 요구사항에 따라, 독자의 학습 수준에 맞춰 깊이 있고 실용적인 프로그래밍 포스트 초안을 작성하는 것입니다.

**[톤앤매너 지침]**
1. **톤:** 전문적이지만 친절하고(Friendly), 권위적(Authoritative)이어야 합니다.
2. **구조:** 모든 포스트는 명확한 논리적 흐름(Introduction -> Core Concepts -> Example/Code -> Conclusion/CTA)을 따라야 합니다.
3. **SEO 최적화:** 제목과 소제목(H2, H3)에는 핵심 키워드를 자연스럽게 포함해야 합니다.
4. **참고:** 항상 독자가 코드를 직접 실행해볼 수 있도록 명확한 예제 코드 블록을 포함해야 합니다.
```

### 2.2. 동적 사용자 프롬프트 (Dynamic User Prompt)

사용자 입력(Input Variables)을 기반으로 LLM에게 구체적인 지시를 내립니다.

| 입력 변수 | 설명 | 프롬프트에 반영될 내용 |
| :--- | :--- | :--- |
| **Topic** | 포스트의 핵심 주제 (예: 비동기 프로그래밍의 이해) | 포스트의 중심 내용 설정 |
| **Target Audience** | 타깃 독자의 기술 수준 (예: 초보자, 중급 개발자, 특정 언어 숙련자) | 사용될 용어의 난이도 및 예제 코드의 복잡도 결정 |
| **Post Style** | 원하는 포스트의 스타일 (예: 튜토리얼, 심층 분석, 비교 리뷰, 문제 해결) | 콘텐츠의 구조와 깊이 결정 |
| **Hook Type** | 도입부 후크 유형 (예: 충격적인 통계 제시, 문제 제기, 흥미로운 비유) | 도입부(Introduction)의 초안 생성 방식 결정 |

**예시 프롬프트 구조:**
> "위의 지침에 따라, [Topic: {입력값}]에 대해 [Target Audience: {입력값}]를 대상으로 [Post Style: {입력값}] 형식의 포스트를 작성해 주세요. 도입부 후크는 [Hook Type: {입력값}]을 사용하며, 핵심은 [핵심 개념 A, B, C]를 실용적인 예제 코드로 설명해야 합니다."

## 3. API 연동 로직 설계 (API Linkage Logic Design)

이 기능은 크게 세 단계의 API 호출로 구성됩니다.

### 단계 1: 입력 및 검증 API (Input & Validation API)

*   **입력:** `Topic`, `Target Audience`, `Post Style`, `Hook Type`

# ⚙️ OpenAI API 연동 및 프롬프트 구조 설계안

## 1. 아키텍처 개요: Chain-of-Thought (CoT) 기반 파이프라인

우리는 단일 프롬프트 호출 대신, **역할 정의(System) → 입력 매핑(Context) → 구조화된 출력(Format)**의 3단계 파이프라인을 구축하여 LLM의 일관성과 정확도를 극대화합니다.

**파이프라인 흐름:**
1. **입력 수집:** 사용자로부터 Topic, Target Audience, 원하는 스타일을 수집합니다.
2. **컨텍스트 주입:** 수집된 입력을 Writer가 설계한 논리(SEO, 교육적 가치)에 맞게 정제합니다.
3. **LLM 실행:** 정제된 컨텍스트와 시스템 프롬프트를 결합하여 초안을 생성하도록 지시합니다.
4. **검증 (선택적):** 생성된 결과물을 구조적 검증(JSON 스키마 준수 여부)을 통해 1차 검증합니다.

## 2. 프롬프트 구조 상세 설계

### 2.1. 시스템 프롬프트 (System Prompt) - 역할 정의

이 부분은 LLM의 **영구적인 행동 규칙**을 정의합니다. Writer의 핵심 가이드라인을 여기에 명시하여 LLM이 항상 이 기준을 따르도록 강제합니다.

```prompt
당신은 전문적인 기술 블로거이자, 복잡한 프로그래밍 개념을 명확하고 이해하기 쉽게 설명하는 교육 콘텐츠 전문가입니다. 당신의 목표는 사용자가 제공한 주제와 요구사항에 따라, 독자의 학습 수준에 맞춰 깊이 있고 실용적인 프로그래밍 포스트 초안을 작성하는 것입니다.

**[핵심 제약 조건 (Constraints)]**
1. **톤앤매너:** 전문적이지만 친절하고(Friendly), 권위적(Authoritative)이어야 합니다.
2. **구조:** 모든 포스트는 명확한 논리적 흐름(Introduction -> Core Concepts -> Example/Code -> Conclusion/CTA)을 따라야 합니다.
3. **SEO:** 제목과 소제목(H2, H3)에는 핵심 키워드를 자연스럽게 포함해야 합니다.
4. **코드:** 모든 예제 코드는 실행 가능하도록 명확한 언어 지정과 적절한 주석을 포함해야 합니다.
5. **출력 형식:** 최종 결과물은 반드시 아래 정의된 JSON 스키마를 준수해야 합니다.
```

### 2.2. 동적 사용자 프롬프트 (Dynamic User Prompt) - 입력 매핑

이 부분은 사용자가 제공하는 **변수(Variables)**를 시스템 프롬프트의 지침에 맞게 매핑하는 부분입니다.

| 입력 변수 (Input) | 설명 | 프롬프트 내 적용 방식 |
| :--- | :--- | :--- |
| **Topic** | 포스트의 핵심 주제 (예: 비동기 프로그래밍의 이해) | `[핵심 주제]` 섹션에 명시. 모든 섹션의 내용이 이 주제에 집중되도록 지시. |
| **Target Audience** | 타깃 독자 수준 (예: 초보 개발자, 시니어 엔지니어) | `[난이도 설정]`에 반영하여 코드의 깊이와 설명의 밀도를 조절. |
| **Style** | 원하는 포스트 스타일 (예: 깊은 이론 중심, 실습 중심, 비즈니스 적용 중심) | `[톤앤매너]`와 `[구조]`에 영향을 주어 최종 결과물의 톤을 결정. |
| **Keywords** | SEO 최적화를 위한 핵심 키워드 목록 | 제목과 H2/H3 태그에 자연스럽게 삽입되도록 강제. |

### 2.3. 출력 구조 정의 (Output Schema) - 구조화된 결과

LLM이 텍스트만 생성하는 것이 아니라, 파싱하기 쉬운 **JSON 형식**으로 출력하도록 강제합니다. 이는 후속 자동화(예: 웹사이트 빌더 연동)의 안정성을 보장합니다.

```json
{
  "title": "string",
  "seo_keywords": ["list of keywords"],
  "introduction": {
    "hook": "string (매력적인 도입부)",
    "context": "string (주제에 대한 배경 설명)"
  },
  "core_concepts": [
    {
      "heading": "H2_Concept_Name",
      "summary": "string (핵심 개념 요약)",
      "details": "string (상세 설명 및 WHY)"
    }
  ],
  "code_examples": [
    {
      "title": "Example_Name",
      "language": "typescript/python/bash",
      "code": "string (실행 가능한 코드 블록)"
    }
  ],
  "conclusion": {
    "summary": "string (전체 내용 요약)",
    "cta": "string (다음 행동 유도)"
  }
}
```

## 3. OpenAI API 호출 전략

**API 호출 방식:** `ChatCompletion` 또는 `Completion` 엔드포인트를 사용하며, `system` 메시지에 **2.1 시스템 프롬프트**를, 사용자 메시지에 **2.2 동적 사용자 프롬프트**와 **2.3 출력 스키마**를 포함하여 전달합니다.

**실행 예시 (개념):**
1. **API Call:** `system` = [System Prompt], `user` = [Dynamic User Prompt + JSON Schema Request]
2. **검증:** API 응답을 수신한 후, JSON 파서(`JSON.parse()`)를 사용하여 출력된 내용이 정의된 스키마를 따르는지 검증합니다.
3. **에러 처리:** JSON 파싱 실패 시, 에러 메시지를 분석하여 LLM에게 재시도(Self-Correction)를 요청하는 루프를 실행합니다.

git rm -r --cached node_modules

git push
